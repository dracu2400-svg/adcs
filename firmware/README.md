# ADCS Firmware for STM32L476RG

This directory contains the firmware for the Attitude Determination and Control System (ADCS) running on the STM32L476RG microcontroller.

## Overview

The ADCS firmware is responsible for:
- **Attitude Determination**: Reading sensor data (magnetometer, gyroscope, sun sensors)
- **Attitude Control**: Controlling 3-axis magnetorquers for spacecraft orientation
- **Telemetry & Communication**: CAN bus interface for system integration
- **Health Monitoring**: Current and temperature monitoring for all magnetorquer coils

## Hardware Specifications

### Target MCU
- **MCU**: STM32L476RG (LQFP64 package)
- **Core**: ARM Cortex-M4F @ 80 MHz
- **Memory**: 1 MB Flash, 128 KB SRAM
- **Key Features**: Ultra-low-power, FPU, DSP instructions

### Peripherals Used
- **CAN1**: Primary communication interface (PC-104 bus)
- **I2C1**: Sensor bus for current, temperature, magnetometer, and gyroscope
- **SPI1**: Alternative interface for magnetometer and gyroscope
- **TIM2/3/4**: PWM generation for magnetorquer H-bridge control
- **GPIO**: Control signals for magnetorquer enable pins and watchdog

### Sensors
| Sensor | Interface | Address/CS | Description |
|--------|-----------|------------|-------------|
| INA226 (×4) | I2C | 0x40-0x43 | Current & voltage monitoring |
| TMP100 (×4) | I2C | 0x48-0x4B | Temperature monitoring |
| MMC5983MA | I2C/SPI | 0x30 | 3-axis magnetometer |
| I3G4250D | I2C/SPI | 0x68 | 3-axis gyroscope |
| Sun Sensors | ADC | - | Photodiode arrays |

### Actuators
- **3× Magnetorquer Coils**: Controlled via H-bridge drivers with PWM (~20 kHz)

## Getting Started

### Prerequisites

You need the following tools installed:

1. **ARM GCC Toolchain**: `arm-none-eabi-gcc` (version 10.3 or later recommended)
   ```bash
   # Ubuntu/Debian
   sudo apt-get install gcc-arm-none-eabi

   # macOS (Homebrew)
   brew install --cask gcc-arm-embedded
   ```

2. **Make**: Build automation tool
   ```bash
   # Ubuntu/Debian
   sudo apt-get install build-essential

   # macOS
   # Already included with Xcode Command Line Tools
   ```

3. **Git**: Version control
   ```bash
   # Ubuntu/Debian
   sudo apt-get install git

   # macOS
   brew install git
   ```

4. **OpenOCD** (optional, for debugging and flashing)
   ```bash
   # Ubuntu/Debian
   sudo apt-get install openocd

   # macOS
   brew install openocd
   ```

### Setup

1. **Download Required Libraries**

   Run the setup script to download STM32 HAL drivers and FreeRTOS:
   ```bash
   ./setup.sh
   ```

   This script will:
   - Clone STM32CubeL4 HAL library from ST's GitHub
   - Clone FreeRTOS kernel from FreeRTOS GitHub
   - Copy necessary files to the correct directories
   - Create configuration headers if they don't exist

2. **Configure HAL and FreeRTOS**

   After running setup.sh, you may need to edit:
   - `Core/Inc/stm32l4xx_hal_conf.h` - Enable/disable HAL modules
   - `Core/Inc/FreeRTOSConfig.h` - Configure FreeRTOS parameters

3. **Update Makefile**

   Edit `Makefile` and uncomment the HAL and FreeRTOS source file lines to include them in the build.

### Building

1. **Build the firmware**:
   ```bash
   make
   ```

   This will generate:
   - `build/adcs_stm32l476rg.elf` - ELF binary with debug symbols
   - `build/adcs_stm32l476rg.hex` - Intel HEX format
   - `build/adcs_stm32l476rg.bin` - Raw binary
   - `build/adcs_stm32l476rg.map` - Memory map

2. **Clean build artifacts**:
   ```bash
   make clean
   ```

### Flashing

#### Using ST-Link

With OpenOCD:
```bash
openocd -f interface/stlink.cfg -f target/stm32l4x.cfg \
        -c "program build/adcs_stm32l476rg.elf verify reset exit"
```

#### Using J-Link

```bash
JLinkExe -device STM32L476RG -if SWD -speed 4000 -autoconnect 1
> loadfile build/adcs_stm32l476rg.hex
> r
> g
> exit
```

## Firmware Architecture

### FreeRTOS Tasks

The firmware uses FreeRTOS for real-time task scheduling:

| Task | Priority | Period | Description |
|------|----------|--------|-------------|
| `Task_AttitudeControl` | 3 (High) | 10 ms | Main control loop for magnetorquer actuation |
| `Task_SensorRead` | 2 (Medium) | 100 ms | Read all sensors (IMU, current, temperature) |
| `Task_CANCommunication` | 2 (Medium) | 50 ms | Handle CAN TX/RX and process commands |
| `Task_Watchdog` | 1 (Low) | 100 ms | Service external watchdog timer |

### Clock Configuration

- **System Clock**: 80 MHz (PLL from MSI)
- **AHB**: 80 MHz
- **APB1**: 80 MHz
- **APB2**: 80 MHz

### Memory Map

| Memory Region | Address Range | Size | Usage |
|---------------|---------------|------|-------|
| Flash | 0x08000000 - 0x080FFFFF | 1 MB | Code and constants |
| SRAM1 | 0x20000000 - 0x20017FFF | 96 KB | Main RAM (stack, heap, .data, .bss) |
| SRAM2 | 0x10000000 - 0x10007FFF | 32 KB | Additional RAM (can be used for DMA) |

## Debugging

### Using GDB with OpenOCD

1. Start OpenOCD in one terminal:
   ```bash
   openocd -f interface/stlink.cfg -f target/stm32l4x.cfg
   ```

2. In another terminal, start GDB:
   ```bash
   arm-none-eabi-gdb build/adcs_stm32l476rg.elf
   (gdb) target extended-remote :3333
   (gdb) monitor reset halt
   (gdb) load
   (gdb) continue
   ```

### Using Visual Studio Code

Install the Cortex-Debug extension and create a launch configuration in `.vscode/launch.json`.
